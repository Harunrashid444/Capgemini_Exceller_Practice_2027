Exam-day setup

Proctoring rules

  • Don't switch tabs or windows. Close every other app and turn off notifications.
  • Keep the room quiet. Background voices or a second person can disqualify you.
  • Put your phone out of reach. A second device counts as malpractice.
  • Keep your face lit and in frame. Stable internet, laptop on charger.

Language choice

  • Pick one language for debugging and coding, Java or C++, and stay with it.
  • Python is often not allowed. Check the language dropdown on the day.
  • Know your input reading cold: Scanner / cin / scanf.

Pacing

  • Technical MCQs: about 1 min each. Skip anything over 90 s and come back to it.
  • Check whether a section lets you go back. Communication didn't, so assume none do.
  • Debugging: read for 3 min, fix in 10, test edge cases for the rest.

Stage 2 · Section A

AI Literacy

These are conceptual MCQs, not maths. Expect scenario questions: "which LLM limitation does this show", "which prompt is better", "what is the responsible action". Learn the terms below, then do the questions.

Core notes

GenAI and LLMs

  • Generative AI creates new content: text, images, audio, code. Discriminative/predictive AI classifies or predicts.
  • LLM: a large language model trained on huge text corpora to predict the next token.
  • Transformer: the architecture behind LLMs. Its key idea is self-attention, where each token weighs every other token. GPT = Generative Pre-trained Transformer.
  • Foundation model: one large pre-trained model adapted to many tasks.
  • Multimodal: handles more than one input type, such as text and images.
  • Diffusion models generate images by gradually removing noise.

How LLMs behave

  • Token: a chunk of text, roughly ¾ of a word. Cost and limits are counted in tokens.
  • Context window: the maximum tokens a model sees at once (prompt plus history plus answer). Beyond it, older content is dropped or "forgotten".
  • Temperature: low (0–0.3) is focused and repeatable, high (0.8+) is creative and varied. Top-p samples from the smallest set of tokens whose total probability is at least p.
  • Max tokens: caps output length. Answers get cut off mid-sentence when it's too low.
  • Knowledge cutoff: the model doesn't know events after its training data ends.

Limitations (scenario favourites)

  • Hallucination: confident but false output, such as fake citations, APIs or case laws.
  • Outdated knowledge: wrong answers about recent events.
  • Bias: reflects skew in its training data.
  • Weak exact reasoning: arithmetic and counting slips.
  • Non-determinism: the same prompt can give different answers.
  • No real understanding or intent, and no access to private data unless you provide it.
  • Prompt sensitivity: small wording changes alter the output.

Prompt engineering

  • A good prompt has Role → Context → Task → Constraints → Output format → Examples.
  • Zero-shot: instruction only. One/Few-shot: include worked input→output examples.
  • Chain-of-thought: "think step by step". It improves multi-step reasoning.
  • Role prompting: "You are a senior Java reviewer…".
  • Prompt chaining: break a big task into sequential prompts.
  • Delimiters (``` or """) separate instructions from data.
  • System prompt: sets persistent behaviour and rules for the whole chat.
  • Iterate: refine the prompt from the output. Be specific, not long.

RAG, fine-tuning, agents

  • RAG (Retrieval-Augmented Generation): retrieve relevant documents, add them to the prompt, then generate. It grounds answers in your data, keeps them current and reduces hallucination.
  • The RAG pipeline: chunk → embed → store in vector DB → embed query → similarity search → augment prompt → generate.
  • Embedding: a numeric vector of meaning. Similar meanings sit close together (cosine similarity).
  • Fine-tuning: further training on your examples to change style or behaviour. Use RAG for changing facts and fine-tuning for a consistent format or tone.
  • AI agent: plans multi-step work, calls tools/APIs, observes results and repeats. Guardrail: human approval before irreversible actions.

Responsible AI

  • Principles: fairness, reliability & safety, privacy & security, inclusiveness, transparency, accountability.
  • Never paste client or confidential data or PII into public AI tools. Use approved enterprise tools and anonymise.
  • Human-in-the-loop for high-stakes decisions (hiring, medical, credit).
  • Always validate AI output: review, test, check facts, licences and security.
  • Prompt injection: hidden instructions in input data hijack the model. Treat retrieved content as data.
  • Explainability: being able to say why the model decided something.
  • Deepfakes: misinformation and consent risks. Label AI-generated content.

ML basics they mix in

  • Supervised: labelled data (classification, regression). Unsupervised: no labels (clustering). Reinforcement: reward-driven.
  • Overfitting: great on training data, poor on test data. Underfitting: poor on both.
  • Precision = TP/(TP+FP), so few false alarms. Recall = TP/(TP+FN), so few misses. Fraud and disease detection favour recall.
  • Model drift: real-world data changes, so accuracy decays over time. Monitor and retrain.

AI in software work

  • Copilot-style tools suggest code. You own it: review, test, understand.
  • Good uses: boilerplate, explaining errors, writing tests, refactoring, docs.
  • Risks: insecure code, invented APIs, licence or IP issues, leaked secrets.
  • Verify before you trust, and never commit code you can't explain.

Neural networks in 6 lines

  • Neuron: weighted sum of inputs + bias → activation (ReLU, sigmoid, softmax).
  • Training: predict → measure loss → backpropagation computes gradients → gradient descent updates weights.
  • Epoch: one full pass over the training data. Learning rate: the size of each update step.
  • CNN for images, RNN/LSTM for older sequence models, Transformer for modern language models.
  • Parameters are the learned weights. "70B model" means 70 billion parameters.
  • Pre-training (huge general data) → fine-tuning → RLHF (reinforcement learning from human feedback) aligns it to be helpful and safe.

Prompting techniques you can be quizzed on

  • Zero / one / few-shot: 0, 1 or a few examples.
  • Chain-of-thought: show reasoning steps.
  • Self-consistency: sample several reasoning paths and take the majority answer.
  • ReAct: Reason → Act (tool call) → Observe, repeated. This is the basis of agents.
  • Tree-of-thought: explore multiple branches of reasoning.
  • Prompt chaining: the output of step 1 feeds step 2.
  • Role / persona, delimiters, output schema (JSON), constraints ("under 100 words", "don't use libraries").
  • Meta-prompting: ask the model to improve your prompt.
  • Rule: specific beats long. Clear goal, context, format and examples.

Reducing hallucinations

  • Ground the model with RAG and ask it to cite which passage it used.
  • Allow "I don't know" or "not found in the document".
  • Lower the temperature for factual tasks.
  • Ask for step-by-step reasoning, then verify the steps.
  • Use tools for maths, dates and live data.
  • Have a human review anything high-stakes. Cross-check with a second source.

RAG one level deeper

  • Chunk size: too big wastes context and adds noise. Too small loses meaning. Overlapping chunks help.
  • Top-k: how many chunks you retrieve. Re-ranking re-orders them for relevance.
  • Hybrid search = keyword (BM25) + vector search. It's better for IDs, codes and names.
  • Bad answer? Check whether it's a retrieval failure (wrong chunks) or a generation failure (right chunks, wrong answer).
  • Keep the index fresh: re-embed when the documents change.
  • Apply access control at retrieval, so users only see documents they're allowed to.

Agents one level deeper

  • Parts: LLM (brain) + tools + memory + planning + orchestration loop.
  • Function / tool calling: the model outputs a structured call, your code runs it, and the result goes back to the model.
  • Memory: short-term (the conversation) vs long-term (a vector store or profile).
  • Multi-agent: specialised agents (planner, coder, reviewer) collaborate.
  • MCP (Model Context Protocol): an open standard for connecting models to tools and data sources.
  • Risks: infinite loops, wrong tool, runaway cost, unsafe actions. Controls: step limits, least privilege, human approval, logging.

Governance and law

  • EU AI Act: risk tiers. Unacceptable is banned (e.g. social scoring). High is regulated (hiring, credit, medical). Limited needs transparency (chatbots must disclose they're AI). Minimal is free (spam filters).
  • GDPR (EU) and India's DPDP Act 2023: consent, purpose limitation, data minimisation, right to erasure.
  • Model cards / datasheets: documentation of what a model or dataset is for and its limits.
  • Red teaming: deliberately attacking a model to find failures before release.
  • Guardrails: input and output filters. Watermarking: marking AI-generated content.
  • Accountability: a human or organisation stays responsible, never "the AI".

Evaluation numbers

100 emails, 25 are spam. The model flags 20, of which 15 are really spam.

  • TP = 15, FP = 5, FN = 10
  • Precision = 15/20 = 75%. Recall = 15/25 = 60%
  • F1 = 2PR/(P+R) ≈ 66.7%
  • Accuracy trap: with 99% legitimate transactions, a model that always says "legit" is 99% accurate and catches zero fraud. Use recall or F1 on imbalanced data.
  • LLM evaluation: human review, LLM-as-judge, benchmarks, groundedness and faithfulness checks.

The model landscape

  • Text and chat: GPT (OpenAI), Claude (Anthropic), Gemini (Google), Llama (Meta, open-weight), Mistral.
  • Images: DALL·E, Midjourney, Stable Diffusion (diffusion models).
  • Code assistants: GitHub Copilot, Cursor, and chat assistants in IDEs.
  • SLMs (small language models): cheaper, faster, can run on-device.
  • Quantisation: lower-precision weights give a smaller, faster model at a small cost in accuracy.
  • Trade-offs: bigger model means better quality but higher cost and latency. Self-hosting is better for data privacy.

Stage 2 · Section B

Situational judgement

Workplace and AI-use scenarios with one best answer. You can almost always find it with the rules below.

Pick the option that…

  1. Takes ownership and acts now. Avoid passive or "wait and see" options.
  2. Communicates early, through the right channel (your lead or manager first).
  3. Protects client data, security and ethics, even if it costs time.
  4. Solves the problem and the relationship: direct, respectful, private.
  5. Escalates only after a reasonable attempt yourself. Ethics and security issues are the exception: escalate at once.
  6. Learns and adapts: ask, upskill, accept feedback.

Eliminate options that…

  • Ignore the issue, hide a mistake, or blame others.
  • Go over someone's head straight away for a small issue.
  • Break policy "just this once" to meet a deadline.
  • Are aggressive, public or emotional.
  • Do the other person's work silently without addressing the issue.
  • Blindly trust AI output or share confidential data with public tools.

Capgemini's stated values: Honesty, Boldness, Trust, Freedom, Team Spirit, Modesty, Fun. Options that show these usually win.

Deep notes: a decision method

Ask these questions in order. The first one that fits tells you which option to look for.

  1. Is it ethics, security, legal, safety or client data? Act and escalate through the proper channel now. Never "just this once", never stay quiet.
  2. Is it your own mistake? Own it, inform your lead quickly, then fix it and prevent it happening again.
  3. Is it someone else's behaviour? Talk to them privately and respectfully first. Escalate only if it continues.
  4. Is something unclear? Ask clarifying questions, check docs and write down your assumptions. Don't guess, and don't wait.
  5. Is it time or workload pressure? Prioritise by impact, tell people early, and offer options (descope, extra help, a new date).
  6. Is it a client request? Be helpful and polite, then route it through your manager or the change process.
  7. Is it about growth or feedback? Accept it, learn and upskill. Ask for specifics.

When two options both look good

  1. Pick the more proactive one: acting now beats waiting.
  2. Pick the one that fixes the root cause, not just the symptom.
  3. Pick the one that involves the right people at the right level: not the CEO for a small issue, not nobody for a serious one.
  4. Pick the one that keeps relationships intact: private beats public.

Words in winning vs losing options

Usually right: inform early, discuss privately, propose a plan, clarify, take ownership, follow policy, document, learn, offer help, verify.

Usually wrong: ignore, wait and see, hope, silently, immediately complain to senior management, blame, refuse outright, publicly, just this once, without telling.

"Most" and "least" effective formats

  • Least effective is usually the option that harms the client, breaks policy, hides a problem, or is aggressive.
  • Passive options ("do nothing") are usually the second-worst choice.
  • For ranking questions, place the extremes (best and worst) first, then the middle ones.

AI at work: the rules behind every AI scenario

  • Use only company-approved AI tools for work data.
  • Never input client-confidential data, source code or personal data into public tools. Anonymise.
  • Verify outputs before you use or ship them. Humans stay accountable.
  • Disclose AI use where policy or the client contract requires it.
  • Report biased, unsafe or wrong outputs. Don't quietly work around them.
  • Respect IP and licences. Don't claim AI output as verified fact.

Data structures

  • Stack is LIFO (undo, recursion, brackets, DFS). Queue is FIFO (BFS, scheduling).
  • BST inorder traversal gives sorted output. A tree with n nodes has n−1 edges.
  • Max nodes in a binary tree of height h (root at height 0): 2^(h+1) − 1.
  • Heap gives fast min/max (priority queue). Hash map gives O(1) average lookup.
  • Insertion sort is stable and good for nearly-sorted data. Merge sort is stable. Quick sort is in-place but not stable.

OOP

  • 4 pillars: Encapsulation, Abstraction, Inheritance, Polymorphism.
  • Overloading: same name, different parameters, decided at compile time. Overriding: subclass redefines the method, decided at runtime.
  • Java has no multiple class inheritance (diamond problem). Use interfaces.
  • Abstract class: can have state and constructors. Interface: a contract.
  • final class can't be extended. final method can't be overridden. static belongs to the class.

DBMS / SQL

  • Clause order: SELECT … FROM … WHERE … GROUP BY … HAVING … ORDER BY.
  • WHERE filters rows before grouping. HAVING filters groups after it.
  • Primary key: unique and NOT NULL. Foreign key: references another table's key.
  • 1NF atomic values · 2NF no partial dependency · 3NF no transitive dependency · BCNF: every determinant is a key.
  • ACID: Atomicity, Consistency, Isolation, Durability.
  • DELETE removes rows and can roll back. TRUNCATE removes all rows fast. DROP removes the table.
  • COUNT(col) skips NULLs. COUNT(*) counts all rows.

OS + Networks

  • Process: own memory. Thread: shares its process's memory.
  • Deadlock needs all four: mutual exclusion, hold-and-wait, no preemption, circular wait.
  • Thrashing: too much paging, CPU idle. Semaphore/mutex: synchronisation.
  • TCP is reliable, ordered and connection-oriented. UDP is fast with no guarantees (video, DNS).
  • DNS maps names to IPs. HTTP uses port 80, HTTPS 443 (TLS).
  • OSI: Physical, Data link, Network, Transport, Session, Presentation, Application.
  • Status codes: 2xx ok (201 created), 3xx redirect, 4xx client error (401, 403, 404), 5xx server error.

Dev basics

  • REST: GET reads, POST creates, PUT replaces, PATCH updates partly, DELETE removes. GET, PUT and DELETE are idempotent.
  • Git: clone, commit, branch, merge. pull = fetch + merge.
  • Cloud: IaaS (VMs, e.g. EC2), PaaS (App Service, Heroku), SaaS (Gmail, Salesforce).
  • Authentication is "who are you". Authorization is "what you're allowed to do".
  • SDLC, Agile: sprints, Scrum, daily stand-up. Testing: unit, integration, system, UAT.

Deep notes: pseudocode tracing

Output questions are the most common type in this section and the easiest to lose marks on. Use a trace table every time: one column per variable, one row per iteration.

Operator rules that decide answers

  • Integer division truncates toward zero: 7/2 = 3, -7/2 = -3.
  • % takes the sign of the dividend (C, Java): -7 % 3 = -1, 7 % -3 = 1.
  • Precedence: * / % → + - → << >> → comparisons → == → & → ^ → | → && → || → ?: → =.
  • Short-circuit: in a && b++, if a is false, b++ never runs.
  • x++ uses the value, then increments. ++x increments, then uses it.
  • Characters: 'A'=65, 'a'=97, '0'=48, 'a'-'A'=32, '7'-'0'=7.
  • C static locals keep their value between calls. Java and C pass primitives by value.
  • Integer overflow wraps: INT_MAX + 1 becomes negative.
  • In C, any non-zero value is true. if (x = 0) is false and sets x to 0.

Loop-count formulas

  • for i=1..n, for j=1..i: n(n+1)/2 iterations. Same for j=i..n.
  • for i=1..n, for j=1..n: n² iterations.
  • i = i*2 until n: about ⌊log₂n⌋ + 1 iterations.
  • while n > 0: n = n/10: number of digits.
  • for i = a to b step s: ⌊(b − a)/s⌋ + 1 iterations.
  • Check the exit value too. After for(i=0;i<5;i++), i is 5.

Recognise the function in 5 seconds

  • n%10 + n/10 → digit work (sum, reverse, palindrome number, Armstrong).
  • r = r*10 + n%10 → reverses the number.
  • gcd(b, a%b) → GCD. a*b/gcd → LCM.
  • f(n-1)+f(n-2) → Fibonacci. Naive fib(5) makes 15 calls.
  • n%2 then n/2 → binary conversion (digits come out reversed).
  • x * f(x, n-1) → power. n * f(n-1) → factorial.
  • Recursion that prints after the recursive call prints in reverse order.

Trees and graphs facts

  • Preorder: Root-L-R. Inorder: L-Root-R (sorted for a BST). Postorder: L-R-Root. Level order uses a queue.
  • Heap stored in an array: children of i are 2i+1 and 2i+2, parent is (i-1)/2.
  • A complete graph with n vertices has n(n−1)/2 edges. A tree has n−1 edges.
  • BFS gives the shortest path in an unweighted graph. Dijkstra needs non-negative weights. Bellman-Ford handles negative weights.
  • Topological sort works only on a DAG. MST algorithms: Kruskal (sort edges, union-find) and Prim.
  • Graph storage: adjacency matrix O(V²) space, adjacency list O(V+E).
  • Prefix, infix and postfix expressions are evaluated with a stack.

Java facts that turn into MCQs

  • Constructors aren't inherited. super() must be the first statement.
  • You can't overload by return type alone. Static methods are hidden, not overridden.
  • Checked exceptions (IOException, SQLException) must be caught or declared. Unchecked ones (NullPointer, Arithmetic, ArrayIndexOutOfBounds) don't need to be.
  • finally always runs, except after System.exit().
  • String is immutable. StringBuilder is fast and not thread-safe. StringBuffer is synchronised.
  • ArrayList: fast random access. LinkedList: fast insert and delete at the ends.
  • HashMap: no order. LinkedHashMap: insertion order. TreeMap: sorted keys. HashSet: no duplicates.
  • An interface can have default and static methods (Java 8+). Its fields are public static final.

C / C++ facts

  • sizeof(char)=1. int is usually 4 bytes. A pointer is 8 bytes on 64-bit.
  • An array name decays to a pointer to its first element. a[i] == *(a+i).
  • Strings end with '\0'. strlen doesn't count it.
  • C uses malloc/free. C++ uses new/delete. A missing free causes a memory leak.
  • virtual functions give runtime polymorphism. A pure virtual function (= 0) makes the class abstract.
  • In a struct members are public by default. In a class they're private by default.
  • References can't be null or reseated. Pointers can.

SOLID, briefly

  • Single responsibility: one reason to change.
  • Open/closed: extend without modifying.
  • Liskov: a subclass must be usable wherever the parent is.
  • Interface segregation: small, focused interfaces.
  • Dependency inversion: depend on abstractions.

Deep notes: DBMS and SQL

Execution order

FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT

That's why a SELECT alias can't be used in WHERE but can be used in ORDER BY.

Command families

Keys and constraints

  • Super key: any set of columns that identifies a row uniquely.
  • Candidate key: a minimal super key. Primary key: the chosen candidate key. Alternate key: the remaining candidate keys.
  • Foreign key: references another table's primary key, enforcing referential integrity.
  • Constraints: NOT NULL, UNIQUE (allows NULLs), CHECK, DEFAULT.
  • NULL = NULL is unknown. Use IS NULL.
  • LIKE: % matches any number of characters, _ matches exactly one.
  • UNION removes duplicates. UNION ALL keeps them and is faster.

Transactions

  • Concurrency problems: dirty read (reading uncommitted data), non-repeatable read (a row changed between reads), phantom read (new rows appear).
  • Isolation levels: Read Uncommitted < Read Committed < Repeatable Read < Serializable.
  • Index: faster reads, slower writes, uses extra space.
  • View: a virtual table defined by a saved query.
  • Normal forms: 1NF atomic values. 2NF no partial dependency on part of a composite key. 3NF no non-key depending on another non-key. BCNF every determinant is a candidate key.

Deep notes: OS and networks

CPU scheduling

  • FCFS: simple. Suffers the convoy effect, where short jobs wait behind a long one.
  • SJF: gives the minimum average waiting time, but long jobs can starve.
  • Round Robin: time quantum, fair, good for time-sharing. A tiny quantum means too many context switches.
  • Priority: can starve low-priority jobs. The fix is aging.
  • Turnaround time = completion − arrival. Waiting time = turnaround − burst.
  • Process states: New → Ready → Running → Waiting → Terminated.

Memory

  • Paging: fixed-size pages, no external fragmentation (some internal). Segmentation: variable-size logical segments.
  • Virtual memory: run programs larger than RAM. A page fault happens when a page isn't in memory.
  • TLB: a cache for page-table lookups.
  • Page replacement: FIFO, LRU, Optimal (the theoretical best). Belady's anomaly: with FIFO, more frames can cause more faults.
  • Thrashing: so much paging that the CPU sits idle.

Synchronisation and deadlock

  • Critical section needs mutual exclusion, progress and bounded waiting.
  • Mutex: a lock with an owner. Semaphore: a counter, either binary or counting.
  • Classic problems: producer-consumer, readers-writers, dining philosophers.
  • Deadlock handling: prevention (break one of the four conditions), avoidance (Banker's algorithm), detection and recovery.

Practice questions

Stage 3 · about 20 minutes, 1 program

Debugging assessment

You get code that compiles badly, crashes or gives wrong output. Fix it so all hidden test cases pass. Usually there are 1–2 bugs. Change as little as possible.

The 5-pass method

  1. Read the spec, then write 3 tests yourself. One normal case, one edge (empty, single element, all equal, negatives) and one boundary (largest index, n = 0 or 1).
  2. Compiler pass. Look for missing ; or } (including the ; after a C++ class), s.length instead of s.length() in Java, "a" where 'a' is needed, wrong return types, undeclared variables.
  3. Boundary pass. Check every loop: < or <=? Start at 0 or 1? Any a[i+1] or a[n-i]? Any off-by-one?
  4. Logic pass. Check initial values (0 vs INT_MIN vs a[0]), accumulators reset per iteration, inverted conditions (!= vs ==, > vs >=), = vs ==, &&/|| precedence, integer division, swaps without a temp, the right return value.
  5. Run your 3 tests. Use custom input if the IDE allows it. Otherwise dry-run by hand. Then submit.

C / C++ traps

  • Uninitialised locals (int sum; holds garbage)
  • Array index past n-1. No bounds check in C
  • if (x = 5) assigns. Use ==
  • Integer overflow. Use long long
  • Missing break in switch
  • Misleading indentation without braces
  • ; after for(...) or if(...) gives an empty body
  • Missing ; after class {}

Java traps

  • == on Strings. Use .equals()
  • s.length() for String, a.length for arrays, list.size() for lists
  • int/int gives an int. Cast to double
  • map.get(k)+1 throws NPE. Use getOrDefault
  • Removing inside for-each throws ConcurrentModificationException
  • char + int gives an int, not a char
  • ArrayIndexOutOfBounds from i <= a.length

Logic traps

  • max/min started at 0 fails on all-negative input
  • Sum or count not reset inside the outer loop
  • >= vs > changes which tie wins
  • Reversal loop runs to n instead of n/2
  • Recursion base case is wrong or missing
  • Binary search: low = mid loops forever
  • Missing empty or null check before pop/access

Deep notes: error message decoder

Java compile errors

  • ';' expected: missing semicolon, usually at the end of the line above.
  • cannot find symbol: typo, undeclared variable, missing import, length vs length().
  • incompatible types: String cannot be converted to char: "a" where 'a' is needed.
  • possible lossy conversion from double to int: add a cast or change the type.
  • missing return statement: some path doesn't return.
  • reached end of file while parsing: missing }.
  • variable might not have been initialized: give it a starting value.
  • unreachable statement: code after return or break.
  • non-static method … from a static context: make it static, or call it on an object.
  • bad operand types for binary operator: e.g. String > int or && on ints.

Java runtime exceptions

  • ArrayIndexOutOfBoundsException / StringIndexOutOfBoundsException: loop bound or index arithmetic.
  • NullPointerException: uninitialised object, map.get returned null.
  • ArithmeticException: / by zero: divide or modulo by 0. Guard it.
  • StackOverflowError: missing or unreachable base case.
  • NumberFormatException: parsing a non-number. Trim the input first.
  • InputMismatchException: Scanner read the wrong type. Check the input format.
  • ConcurrentModificationException: modifying a list inside for-each.
  • ClassCastException: wrong downcast.

C / C++ errors

  • expected ';' before … / expected ';' after class definition.
  • 'x' was not declared in this scope: typo, missing include, or the variable is used outside its block.
  • invalid conversion from 'const char*' to 'char': "a" vs 'a'.
  • no matching function for call: wrong argument types or count.
  • control reaches end of non-void function: missing return.
  • undefined reference to …: a function is declared but never defined (linker error).
  • Segmentation fault: out-of-bounds access, null pointer dereference, very deep recursion.
  • Floating point exception: integer division by zero.

Stage 4 · about 45 minutes

AI-assisted coding

You solve a coding task by directing an on-screen AI assistant. You are scored on AI literacy, prompt quality, problem solving, and review and adaptation. The examiner sees your conversation, so a correct answer pasted after one lazy prompt scores worse than a clean, guided process.

The workflow

  1. Understand first (2–3 min, no AI). Write down the inputs, outputs, constraints, edge cases and the input format.
  2. State your approach. Pick the algorithm and complexity yourself, e.g. "HashSet, single pass, O(n)". Then the AI implements your plan.
  3. One structured prompt. Use the template below. Name the language, function signature, I/O format, constraints and edge cases.
  4. Review before running. Read every line. Does it follow your approach? Handle empty input? Read input in the exact format? Avoid overflow?
  5. Test. Run the sample cases, then your edge cases. Ask the AI for extra edge-case tests if useful.
  6. Targeted fix. If a case fails, give the exact failing input, expected and actual output, and ask for a minimal fix. Don't say "it doesn't work, rewrite it".
  7. Finish. Ask it to explain the complexity, make sure the code is clean and commented, then submit.

Stage 5 · game-based

Cognitive assessment

Short adaptive games plus a personality questionnaire. You can't cram these, but knowing the rules and a strategy beforehand is a real advantage.

Motion Challenge

A grid holds a red ball, a hole and blocks. Slide blocks and the ball to get the ball into the hole in as few moves as possible. Each puzzle has a time limit, and the total time is fixed. More puzzles solved means a higher score.

  • Work backwards from the hole: which cell must be free?
  • Count the minimum moves shown, if displayed. Don't settle for a long solution when a shorter one is obvious.
  • If a puzzle drags past about 40 s, finish it with any valid route. Unsolved puzzles cost the most.

Grid Challenge

A dot flashes in a 4×4 grid. Between flashes you answer a distractor task (symmetry, or rotated-shape match). At the end you recall the dot positions in order.

  • Encode positions as row/col pairs ("2-3, 4-1, 1-1") and repeat them silently.
  • Or use shapes: link consecutive dots into a path picture.
  • Do the distractor quickly but correctly. It's scored too.
  • Practise with the drill below.

Logical Reasoning (Switch / inductive / deductive)

Switch challenge: input symbols pass through a "switch" and come out reordered. Pick the code that explains it. Code digit k tells you which input position lands in output position k.

  • Input A B C D → output C A D B means the code is 3142.
  • Inductive: find the rule in a series of figures (rotation, count, shading, position).
  • Deductive: syllogisms. If a valid conclusion isn't forced, it doesn't follow.

Behavioural module (ADEPT-15 style)

This is a personality questionnaire, usually a choice between two statements. There are no right answers, but consistency is checked across repeated items.

  • Answer as your honest best professional self. Don't try to game it.
  • Traits that fit consulting and IT services: collaborative, adaptable, composed under pressure, open to feedback, structured, takes initiative, client-focused.
  • Avoid extremes that read as rigid or as avoiding responsibility.
  • Don't overthink. Take 5–10 s per item.

Deep notes: game strategies

Motion Challenge, step by step

  1. Look at the straight path from the ball to the hole. Which blocks sit on it?
  2. For each blocking block, find where it can move to clear the path.
  3. If that spot is blocked too, repeat one level deeper. Work backwards.
  4. Move in the order that makes the fewest total moves.
  5. Bail-out rule: after about 40 seconds on one puzzle, finish with any valid solution.

Scoring rewards both the number solved and efficiency. A long solution beats no solution.

Grid Challenge, step by step

  • Name each dot position as soon as it flashes: "row 2, column 3" → "2-3".
  • Rehearse the whole list every time a new dot is added.
  • Symmetry distractor: mentally fold the figure down the vertical middle line. Compare the outer columns first, then the inner ones. One mismatch means not symmetric.
  • Rotation distractor: track one distinctive corner or feature. Don't rotate the whole shape in your head.
  • If you lose a dot, still enter the ones you're sure of in the right slots.

Switch Challenge, fast method

  • Track one symbol: where did input 1 end up? Eliminate options that disagree.
  • Usually 1–2 checks leave a single option, so you don't need to verify all four positions.
  • With two switches, apply the first, write the middle state down, then find the second.
  • Speed matters. Aim for under 15 seconds per item once you're warmed up.

Inductive pattern checklist

  1. Count: elements, sides, dots, lines
  2. Rotation: 45°, 90° or 180° per step
  3. Position: moving clockwise or along a row
  4. Shading: alternating or cycling
  5. Size: growing or shrinking
  6. Two rules at once on different elements
  7. Odd one out: the figure breaking the one rule all the others share

Deductive reasoning

  • Use only what the statements say. Ignore real-world knowledge.
  • "Some" means at least one, possibly all.
  • Draw Venn circles. A conclusion follows only if it's true in every diagram.
  • For arrangement puzzles, place fixed facts first, then the relative ones ("left of", "between").

Stamina across back-to-back stages

  • Eat something light before you start, and keep water nearby.
  • Take any break allowed between stages. Look away from the screen for 30 seconds.
  • The cognitive games come last, when you're most tired. Expect it and stay deliberate.
  • Use a mouse if you can. Trackpads slow down the motion and grid games.

Last-look cheat sheet

AI Literacy

  • Hallucination = confident and false. Cutoff = outdated.
  • RAG = retrieve then generate. Grounded, current, private data.
  • Fine-tune = behaviour or style. RAG = facts that change.
  • Temperature low = deterministic.
  • Few-shot = examples in the prompt. CoT = step by step.
  • Agent = plans + tools + loop. Needs human approval for risky steps.
  • Prompt injection = instructions hidden in data.
  • No client data or PII in public AI. Always validate output.
  • Precision = few false alarms. Recall = few misses.

Situational

  • Own it → communicate early → protect data and ethics → respectful and private → escalate after trying (except ethics: at once) → learn.

Reasoning

  • Series: check differences, then ratios, then squares/cubes, then ×k ± c.
  • +20% then −20% = −4%. Work: 1/A + 1/B.
  • Clock: |30H − 5.5M|.

Debugging

  • Compiler → boundary → logic → test.
  • <= length · a[i+1] · len-i vs len-1-i
  • max = 0 for negatives · sum not reset · = vs ==
  • Java: .equals, length(), (double), getOrDefault
  • C++: ; after class, uninitialised vars, long long
  • Stack: check empty before pop, and empty at the end

AI-assisted coding

  • Understand → approach → structured prompt → review → test → targeted fix → explain.
  • Always give: language, I/O format, constraints, approach, edge cases.
  • Fix with "input X gives Y, expected Z. Minimal change."

Cognitive

  • Motion: work backwards, few moves, don't stall.
  • Grid: encode row-col and rehearse.
  • Behavioural: consistent and honest.
