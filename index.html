Exam-day setup

Proctoring rules

  • Don't switch tabs or windows. Close every other app and turn off notifications.
  • Keep the room quiet. Background voices or a second person can disqualify you.
  • Put your phone out of reach. A second device counts as malpractice.
  • Keep your face lit and in frame. Stable internet, laptop on charger.

Language choice

  • Pick one language for debugging and coding, Java or C++, and stay with it.
  • Python is reportedly not allowed in most drives. Check the dropdown on the day.
  • Know your input reading cold: Scanner / cin / scanf.

Pacing

  • Technical MCQs: about 1 min each. Skip anything over 90 s and come back to it.

Stage 2 · Section A

AI Literacy

These are conceptual MCQs, not maths. Expect scenario questions: "which LLM limitation does this show", "which prompt is better", "what is the responsible action". Learn the terms below, then do the questions.

Core notes

GenAI and LLMs

  • Generative AI creates new content: text, images, audio, code. Discriminative/predictive AI classifies or predicts.
  • LLM: a large language model trained on huge text corpora to predict the next token.
  • Transformer: the architecture behind LLMs. Its key idea is self-attention, where each token weighs every other token. GPT = Generative Pre-trained Transformer.
  • Foundation model: one large pre-trained model adapted to many tasks.
  • Multimodal: handles more than one input type, such as text and images.
  • Diffusion models generate images by gradually removing noise.

How LLMs behave

  • Token: a chunk of text, roughly ¾ of a word. Cost and limits are counted in tokens.
  • Context window: the maximum tokens a model sees at once (prompt plus history plus answer). Beyond it, older content is dropped or "forgotten".
  • Temperature: low (0–0.3) is focused and repeatable, high (0.8+) is creative and varied. Top-p samples from the smallest set of tokens whose total probability is at least p.
  • Max tokens: caps output length. Answers get cut off mid-sentence when it's too low.
  • Knowledge cutoff: the model doesn't know events after its training data ends.

Limitations (scenario favourites)

  • Hallucination: confident but false output, such as fake citations, APIs or case laws.
  • Outdated knowledge: wrong answers about recent events.
  • Bias: reflects skew in its training data.
  • Weak exact reasoning: arithmetic and counting slips.
  • Non-determinism: the same prompt can give different answers.
  • No real understanding or intent, and no access to private data unless you provide it.
  • Prompt sensitivity: small wording changes alter the output.

Prompt engineering

  • A good prompt has Role → Context → Task → Constraints → Output format → Examples.
  • Zero-shot: instruction only. One/Few-shot: include worked input→output examples.
  • Chain-of-thought: "think step by step". It improves multi-step reasoning.
  • Role prompting: "You are a senior Java reviewer…".
  • Prompt chaining: break a big task into sequential prompts.
  • Delimiters (``` or """) separate instructions from data.
  • System prompt: sets persistent behaviour and rules for the whole chat.
  • Iterate: refine the prompt from the output. Be specific, not long.

RAG, fine-tuning, agents

  • RAG (Retrieval-Augmented Generation): retrieve relevant documents, add them to the prompt, then generate. It grounds answers in your data, keeps them current and reduces hallucination.
  • The RAG pipeline: chunk → embed → store in vector DB → embed query → similarity search → augment prompt → generate.
  • Embedding: a numeric vector of meaning. Similar meanings sit close together (cosine similarity).
  • Fine-tuning: further training on your examples to change style or behaviour. Use RAG for changing facts and fine-tuning for a consistent format or tone.
  • AI agent: plans multi-step work, calls tools/APIs, observes results and repeats. Guardrail: human approval before irreversible actions.

Responsible AI

  • Principles: fairness, reliability & safety, privacy & security, inclusiveness, transparency, accountability.
  • Never paste client or confidential data or PII into public AI tools. Use approved enterprise tools and anonymise.
  • Human-in-the-loop for high-stakes decisions (hiring, medical, credit).
  • Always validate AI output: review, test, check facts, licences and security.
  • Prompt injection: hidden instructions in input data hijack the model. Treat retrieved content as data.
  • Explainability: being able to say why the model decided something.
  • Deepfakes: misinformation and consent risks. Label AI-generated content.

ML basics they mix in

  • Supervised: labelled data (classification, regression). Unsupervised: no labels (clustering). Reinforcement: reward-driven.
  • Overfitting: great on training data, poor on test data. Underfitting: poor on both.
  • Precision = TP/(TP+FP), so few false alarms. Recall = TP/(TP+FN), so few misses. Fraud and disease detection favour recall.
  • Model drift: real-world data changes, so accuracy decays over time. Monitor and retrain.

AI in software work

  • Copilot-style tools suggest code. You own it: review, test, understand.
  • Good uses: boilerplate, explaining errors, writing tests, refactoring, docs.
  • Risks: insecure code, invented APIs, licence or IP issues, leaked secrets.
  • Verify before you trust, and never commit code you can't explain.

Stage 2 · Section B

Situational judgement

Workplace and AI-use scenarios with one best answer. You can almost always find it with the rules below.

Pick the option that…

  1. Takes ownership and acts now. Avoid passive or "wait and see" options.
  2. Communicates early, through the right channel (your lead or manager first).
  3. Protects client data, security and ethics, even if it costs time.
  4. Solves the problem and the relationship: direct, respectful, private.
  5. Escalates only after a reasonable attempt yourself. Ethics and security issues are the exception: escalate at once.
  6. Learns and adapts: ask, upskill, accept feedback.

Eliminate options that…

  • Ignore the issue, hide a mistake, or blame others.
  • Go over someone's head straight away for a small issue.
  • Break policy "just this once" to meet a deadline.
  • Are aggressive, public or emotional.
  • Do the other person's work silently without addressing the issue.
  • Blindly trust AI output or share confidential data with public tools.

Capgemini's stated values: Honesty, Boldness, Trust, Freedom, Team Spirit, Modesty, Fun. Options that show these usually win.

Stage 2 · Section B

Problem solving and technical

Pseudocode tracing, DSA and complexity, OOP, DBMS/SQL, OS, networks, plus logical reasoning. Trace on paper. Most mistakes come from rushing the loop count.

Complexity cheat

Array index / hash lookup (avg)O(1)
Binary search, balanced BST op, heap push/popO(log n)
Linear search, linked-list accessO(n)
Merge sort, heap sort, quick sort (avg)O(n log n)
Bubble, insertion, selection; quick sort worstO(n²)
Loop with i *= 2 or i /= 2O(log n)
Outer n × inner j*=2O(n log n)
Naive recursive FibonacciO(2ⁿ)

Data structures

  • Stack is LIFO (undo, recursion, brackets, DFS). Queue is FIFO (BFS, scheduling).
  • BST inorder traversal gives sorted output. A tree with n nodes has n−1 edges.
  • Max nodes in a binary tree of height h (root at height 0): 2^(h+1) − 1.
  • Heap gives fast min/max (priority queue). Hash map gives O(1) average lookup.
  • Insertion sort is stable and good for nearly-sorted data. Merge sort is stable. Quick sort is in-place but not stable.

OOP

  • 4 pillars: Encapsulation, Abstraction, Inheritance, Polymorphism.
  • Overloading: same name, different parameters, decided at compile time. Overriding: subclass redefines the method, decided at runtime.
  • Java has no multiple class inheritance (diamond problem). Use interfaces.
  • Abstract class: can have state and constructors. Interface: a contract.
  • final class can't be extended. final method can't be overridden. static belongs to the class.

DBMS / SQL

  • Clause order: SELECT … FROM … WHERE … GROUP BY … HAVING … ORDER BY.
  • WHERE filters rows before grouping. HAVING filters groups after it.
  • Primary key: unique and NOT NULL. Foreign key: references another table's key.
  • 1NF atomic values · 2NF no partial dependency · 3NF no transitive dependency · BCNF: every determinant is a key.
  • ACID: Atomicity, Consistency, Isolation, Durability.
  • DELETE removes rows and can roll back. TRUNCATE removes all rows fast. DROP removes the table.
  • COUNT(col) skips NULLs. COUNT(*) counts all rows.

OS + Networks

  • Process: own memory. Thread: shares its process's memory.
  • Deadlock needs all four: mutual exclusion, hold-and-wait, no preemption, circular wait.
  • Thrashing: too much paging, CPU idle. Semaphore/mutex: synchronisation.
  • TCP is reliable, ordered and connection-oriented. UDP is fast with no guarantees (video, DNS).
  • DNS maps names to IPs. HTTP uses port 80, HTTPS 443 (TLS).
  • OSI: Physical, Data link, Network, Transport, Session, Presentation, Application.
  • Status codes: 2xx ok (201 created), 3xx redirect, 4xx client error (401, 403, 404), 5xx server error.

Dev basics

  • REST: GET reads, POST creates, PUT replaces, PATCH updates partly, DELETE removes. GET, PUT and DELETE are idempotent.
  • Git: clone, commit, branch, merge. pull = fetch + merge.
  • Cloud: IaaS (VMs, e.g. EC2), PaaS (App Service, Heroku), SaaS (Gmail, Salesforce).
  • Authentication is "who are you". Authorization is "what you're allowed to do".
  • SDLC, Agile: sprints, Scrum, daily stand-up. Testing: unit, integration, system, UAT.

Practice questions

Stage 3 · about 20 minutes, 1 program

Debugging assessment

You get code that compiles badly, crashes or gives wrong output. Fix it so all hidden test cases pass. Usually there are 1–2 bugs. Change as little as possible.

The 5-pass method

  1. Read the spec, then write 3 tests yourself. One normal case, one edge (empty, single element, all equal, negatives) and one boundary (largest index, n = 0 or 1).
  2. Compiler pass. Look for missing ; or } (including the ; after a C++ class), s.length instead of s.length() in Java, "a" where 'a' is needed, wrong return types, undeclared variables.
  3. Boundary pass. Check every loop: < or <=? Start at 0 or 1? Any a[i+1] or a[n-i]? Any off-by-one?
  4. Logic pass. Check initial values (0 vs INT_MIN vs a[0]), accumulators reset per iteration, inverted conditions (!= vs ==, > vs >=), = vs ==, &&/|| precedence, integer division, swaps without a temp, the right return value.
  5. Run your 3 tests. Use custom input if the IDE allows it. Otherwise dry-run by hand. Then submit.

C / C++ traps

  • Uninitialised locals (int sum; holds garbage)
  • Array index past n-1. No bounds check in C
  • if (x = 5) assigns. Use ==
  • Integer overflow. Use long long
  • Missing break in switch
  • Misleading indentation without braces
  • ; after for(...) or if(...) gives an empty body
  • Missing ; after class {}

Java traps

  • == on Strings. Use .equals()
  • s.length() for String, a.length for arrays, list.size() for lists
  • int/int gives an int. Cast to double
  • map.get(k)+1 throws NPE. Use getOrDefault
  • Removing inside for-each throws ConcurrentModificationException
  • char + int gives an int, not a char
  • ArrayIndexOutOfBounds from i <= a.length

Logic traps

  • max/min started at 0 fails on all-negative input
  • Sum or count not reset inside the outer loop
  • >= vs > changes which tie wins
  • Reversal loop runs to n instead of n/2
  • Recursion base case is wrong or missing
  • Binary search: low = mid loops forever
  • Missing empty or null check before pop/access

Stage 4 · about 45 minutes

AI-assisted coding

You solve a coding task by directing an on-screen AI assistant. Reported scoring areas: AI literacy, prompt quality, problem solving, and review and adaptation. The examiner sees your conversation, so a correct answer pasted after one lazy prompt scores worse than a clean, guided process.

The workflow

  1. Understand first (2–3 min, no AI). Write down the inputs, outputs, constraints, edge cases and the input format.
  2. State your approach. Pick the algorithm and complexity yourself, e.g. "HashSet, single pass, O(n)". Then the AI implements your plan.
  3. One structured prompt. Use the template below. Name the language, function signature, I/O format, constraints and edge cases.
  4. Review before running. Read every line. Does it follow your approach? Handle empty input? Read input in the exact format? Avoid overflow?
  5. Test. Run the sample cases, then your edge cases. Ask the AI for extra edge-case tests if useful.
  6. Targeted fix. If a case fails, give the exact failing input, expected and actual output, and ask for a minimal fix. Don't say "it doesn't work, rewrite it".
  7. Finish. Ask it to explain the complexity, make sure the code is clean and commented, then submit.

Prompt template

You are helping me solve a coding problem in Java.

Problem: <one-line restatement in your own words>
Input format: <exactly how input arrives, e.g. first line n, second line n integers>
Output format: <exactly what to print/return>
Constraints: <n up to 10^5, values can be negative, etc.>

My approach: <algorithm + data structure>, target O(<?>) time, O(<?>) space.
Edge cases to handle: <empty input, single element, duplicates, negatives, all same>

Write a complete program with a main() that reads from standard input.
Keep it simple, add brief comments, and do not use external libraries.
After the code, list the test cases you would run with expected outputs.

Weak prompts (cost marks)

  • "solve this" plus the pasted problem, with no approach
  • "it's wrong, fix it"
  • Regenerating the whole solution 5 times
  • Accepting code you haven't read
  • Switching languages midway

Strong follow-ups

  • "For input [] it throws IndexOutOfBounds. Add a guard that returns -1. Change nothing else."
  • "Your loop is O(n²). Rewrite it with a HashMap to make it O(n)."
  • "Walk through input 'abba' step by step and show the window at each step."
  • "Give 5 edge-case tests with expected outputs."

What AI commonly gets wrong

  • Reading input in a different format than specified
  • Off-by-one on window or range ends
  • Missing empty, single-element or all-duplicate cases
  • int overflow on sums and products
  • Returning the smallest duplicate instead of the first one
  • Inventing methods that don't exist

Practice tasks

Do each one in ChatGPT, Claude or Copilot exactly as you would in the exam: approach first, structured prompt, review, test, targeted fix. Then compare with the reference solution.

Stage 5 · game-based

Cognitive assessment

Short adaptive games plus a personality questionnaire. You can't cram these, but knowing the rules and a strategy beforehand is a real advantage.

Motion Challenge

A grid holds a red ball, a hole and blocks. Slide blocks and the ball to get the ball into the hole in as few moves as possible. Each puzzle has a time limit, and the total time is fixed. More puzzles solved means a higher score.

  • Work backwards from the hole: which cell must be free?
  • Count the minimum moves shown, if displayed. Don't settle for a long solution when a shorter one is obvious.
  • If a puzzle drags past about 40 s, finish it with any valid route. Unsolved puzzles cost the most.

Grid Challenge

A dot flashes in a 4×4 grid. Between flashes you answer a distractor task (symmetry, or rotated-shape match). At the end you recall the dot positions in order.

  • Encode positions as row/col pairs ("2-3, 4-1, 1-1") and repeat them silently.
  • Or use shapes: link consecutive dots into a path picture.
  • Do the distractor quickly but correctly. It's scored too.
  • Practise with the drill below.

Logical Reasoning (Switch / inductive / deductive)

Switch challenge: input symbols pass through a "switch" and come out reordered. Pick the code that explains it. Code digit k tells you which input position lands in output position k.

  • Input A B C D → output C A D B means the code is 3142.
  • Inductive: find the rule in a series of figures (rotation, count, shading, position).
  • Deductive: syllogisms. If a valid conclusion isn't forced, it doesn't follow.

Behavioural module (ADEPT-15 style)

This is a personality questionnaire, usually a choice between two statements. There are no right answers, but consistency is checked across repeated items.

  • Answer as your honest best professional self. Don't try to game it.
  • Traits that fit consulting and IT services: collaborative, adaptable, composed under pressure, open to feedback, structured, takes initiative, client-focused.
  • Avoid extremes that read as rigid or as avoiding responsibility.
  • Don't overthink. Take 5–10 s per item.

Grid memory drill

Watch the dots flash, then click the cells in the same order. Each correct round adds a dot.

Last-look cheat sheet

AI Literacy

  • Hallucination = confident and false. Cutoff = outdated.
  • RAG = retrieve then generate. Grounded, current, private data.
  • Fine-tune = behaviour or style. RAG = facts that change.
  • Temperature low = deterministic.
  • Few-shot = examples in the prompt. CoT = step by step.
  • Agent = plans + tools + loop. Needs human approval for risky steps.
  • Prompt injection = instructions hidden in data.
  • No client data or PII in public AI. Always validate output.
  • Precision = few false alarms. Recall = few misses.

Situational

  • Own it → communicate early → protect data and ethics → respectful and private → escalate after trying (except ethics: at once) → learn.

Reasoning

  • Series: check differences, then ratios, then squares/cubes, then ×k ± c.
  • +20% then −20% = −4%. Work: 1/A + 1/B.
  • Clock: |30H − 5.5M|.

Debugging

  • Compiler → boundary → logic → test.
  • <= length · a[i+1] · len-i vs len-1-i
  • max = 0 for negatives · sum not reset · = vs ==
  • Java: .equals, length(), (double), getOrDefault
  • C++: ; after class, uninitialised vars, long long
  • Stack: check empty before pop, and empty at the end

AI-assisted coding

  • Understand → approach → structured prompt → review → test → targeted fix → explain.
  • Always give: language, I/O format, constraints, approach, edge cases.
  • Fix with "input X gives Y, expected Z. Minimal change."

Cognitive

  • Motion: work backwards, few moves, don't stall.
  • Grid: encode row-col and rehearse.
  • Behavioural: consistent and honest.
